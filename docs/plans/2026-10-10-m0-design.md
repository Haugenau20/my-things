# M0 foundation design

Implement only the foundation described in the existing specification and roadmap.
The owner approved mise as the toolchain manager; no cloud access or deployment is
required. Preserve all starter documents and the existing MIT license.

Use exact Node LTS and Temurin Java pins in `mise.toml`, npm with a committed lockfile,
and a project-local Firebase CLI. npm scripts remain the command contract. A minimal
React shell distinguishes signed out, checking access, authorized, denied, and service
failure states. Authorization comes from a trusted inventory root, never a client UID
setting. Use session-scoped Auth persistence and in-memory Firestore data only.

Validate configuration before importing/initializing the Firebase runtime. Local
configuration requires `demo-inventory` and all three loopback emulator endpoints.
Local startup checks the emulator suite before serving the app. Cloud builds require
explicit, distinct development and production destinations; deployment preflight
rejects local builds and mismatched destinations. No deployment command is added.

Initial rules allow the owner to read the documented namespace and update validated
inventory settings. Child writes remain denied until their feature and schemas are
implemented in later milestones. Storage owner access is restricted to valid photo
paths, JPEG variants and byte limits; scoped listing and deletion are tested separately.
Synthetic Auth users and an inventory root are seeded through emulator-only trusted
tooling. No first-user claiming, real data, admin credentials, or private frontend values.

Write configuration, seed-isolation, authorization and browser tests before their
implementations. Verify lint/formatting, strict typecheck, unit tests, emulator rules
and SDK integration, browser flows, and build. Document actual evidence and remaining
cloud/device checks; do not represent M0 as a usable inventory or a backup proof.
