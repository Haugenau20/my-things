# M1 capture design

The owner authorized M1 after merging M0. Use the settled SPEC, data model, photo pipeline, and security
contracts. One production cloud project is configured; normal development and all automated checks use
`demo-inventory`. App Check remains deferred, Analytics absent, and cloud deployment/administrative
bootstrap require a concrete reviewed release and explicit authorization.

## Implementation slices

1. Strict item/room/photo schemas, capture defaults, stable attempt identity, and metadata/path/hash
   validation. Cover and ready state are derived only after every selected photo has both variants.
2. Feature-specific Firestore rules for draft creation, revision-checked completion, explicit draft
   discard, and simple room creation. Keep M2 edits, box writes, ready-item deletion, and root claiming
   closed. Storage objects are never silently replaced with different bytes.
3. Small repositories for server reads, stable draft creation, transactions, and bounded discard cleanup.
   Upload/download modules verify exact planned bytes, preserve recoverable failures, and release memory.
4. Sequential browser JPEG processing, image size guards, normalized orientation, metadata stripping,
   resumable upload progress, authenticated lazy photos, and session-scoped object URLs.
5. Google redirect sign-in on an origin matching authDomain, capture/save-next, sticky room, recovery,
   minimal gallery/details, and immediate cancellation/clearing on sign-out and account changes.
6. Positive/negative domain, rules, SDK, and browser checks; static production build and reviewable release
   configuration. Document remaining actual iPhone/OAuth/CORS/IAM/label-quality tests honestly.

Browser-native HEIC decode is attempted; unsupported input gets a clear reselection/conversion message.
No HEIC dependency is added before a real-device need is established. Originals are not uploaded or
modified. No offline queue, organization workflow, backup/restore implementation, or new backend is added.

Prepared attempts keep stable IDs in memory. Recovery reads server drafts after reload, checks existing
objects by size/hash, and can complete fully uploaded attempts without source files. Missing derivatives
require reselecting the original files with matching generated metadata, or explicit discard followed
by a new capture. Discard first leaves a durable deleting marker, cleans the exact item prefix with
bounded paginated operations, and deletes the draft record last. Partial cleanup remains retryable.

Review artifacts will include exact automated check results, deployable configuration, trusted console
bootstrap instructions, and manual cloud/device checklist. Local checks do not complete the real-device
M1 acceptance gate or constitute backup proof.
